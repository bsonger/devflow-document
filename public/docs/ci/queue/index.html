        🧵 队列与并发控制#

        Tekton ⚖️ Priority 📏 Quota

        当很多人同时发版时，CI 集群可能会被压垮。DevFlow 提供了几种策略来控制构建的排队和并发。

        🛣️ 四种排队策略#

        FIFO — 先来后到#

        按提交顺序排队，先到先构建。最简单、最公平。

        适合：资源充足，不需要区分优先级的场景。

        Priority — 优先级#

        给不同的构建设置优先级：

        优先级场景
        高生产环境热修复
        中日常开发构建
        低文档更新、依赖升级

        生产环境的紧急补丁应该优先构建，内部工具的更新可以等等。

        Per-Repo — 按仓库限流#

        每个仓库最多同时跑 N 个构建。防止某个仓库的频繁提交独占 CI 资源。

        适合：多团队共享 CI 集群，需要资源隔离。

        Per-Cluster — 多集群分流#

        构建任务分发到多个 CI 集群执行，水平扩展。

        适合：超大规模构建，单集群撑不住。

        ☸️ Kubernetes 里的实现#

        Tekton 跑在 Kubernetes 上，排队和并发控制通过 K8s 原生机制实现：

        PriorityClass — 设置优先级#

        给 PipelineRun 打上优先级标签，高优先级的任务可以先调度。

        ResourceQuota — 限制总资源#

        限制 CI 命名空间最多能用多少 CPU 和内存，防止构建把集群资源吃光。

        LimitRange — 限制单个任务#

        限制单个构建 Pod 最多能用多少资源，防止一个构建任务独占节点。

        📈 关键监控指标#

        指标说明告警建议
        队列深度有多少构建在排队> 20 时告警
        等待时间从提交到开始构建等了多久> 5 分钟时告警
        构建成功率失败构建的比例> 5% 时告警
